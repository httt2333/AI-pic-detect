# UX Writing + Content Design Review V2

用于 AI-PIC-DETECT 的首次用户体验、UX Writing、Content Design 和可用性审查。只用于审查和提出建议，不自动修改产品代码，不扩展产品范围。

## 核心目标

每个页面都要让首次用户快速知道：

1. 这是什么产品；
2. 现在发生了什么；
3. 结果意味着什么；
4. 下一步可以做什么；
5. 系统确定了什么、哪些仍不确定。

文字是交互的一部分。必须结合真实页面、真实行为和完整用户旅程检查，不能孤立润色文案。

## AI-PIC-DETECT 产品边界

产品是发布前的单图局部复核工具，不是 AI 真伪鉴定器。AI 负责发现、定位和解释可能的视觉疑点；用户负责确认、排除和决定是否修改。

不得暗示：100% 判断、绝对没有问题、自动修复、固定问题数量或确定性 AI 结论。

## 首选词汇

| 产品概念 | 用户可见首选词 |
|---|---|
| analyze / scan | 检查 |
| candidate issue | 疑点 |
| reason | 为什么值得注意 |
| suggestion | 可以怎么改 |
| retry | 再试一次 |
| confirmed | 确认疑点 |
| dismissed | 排除疑点 |
| next item | 看下一处 |

避免在用户界面混用“扫描、分析、候选问题、异常维度、AI 判定、高置信度、Provider、model timeout”等内部或过度确定的说法。

## 8 项文案检查

每条重要文案都检查：清楚、简洁、可行动、一致、诚实、像人说话、符合当前上下文、降低犹豫和焦虑。

## 品牌语言与任务语言

品牌层可以有记忆点，例如“让你的 AI 图，经得住细看”。

任务层必须直白、冷静、可预测，例如“上传一张 AI 图”“开始检查”“再试一次”。不要在核心流程使用过度主题化的侦探、案件、破案等表达；可以借用“疑点、发现、确认、排除、再看一眼”的逻辑。

## 页面与状态审查顺序

按真实旅程检查：

Landing → 上传 → 格式/大小校验 → 预览 → 等待 → success → 结果 → 确认/排除 → 完成 → no_issue → failed → retry → 再次操作。

任务页的信息层级应为：当前状态或结果 → 主要含义 → 解释 → 可用操作 → 次要细节。

## 状态规则

### Loading

只描述真实发生的状态。可以说明正在检查容易被忽略的细节、完成后会显示位置/原因/调整方向；不得伪造进度百分比、倒计时、模型阶段或“正在检查手部”等后端未知状态。等待时间若显示，必须真实开始、递增、停止并在重试时重置。

### Error

每个错误回答“发生了什么”和“如何恢复”。原因未知时不要编造技术原因，不泄露 provider、模型、堆栈或基础设施术语，不责怪用户。

### Empty / no_issue

说明“没有找到足够明确、值得单独标出的疑点”，并提供下一步。避免“图片没有问题”等绝对判断。

### Success / completion

明确说明“这次检查完成了”，随后提供必要操作即可。确认/排除后必须反馈真实的数据状态；“看下一处”只能导航，不能隐式确认或排除。

## AI 结果三层结构

1. 观察：看到了什么；
2. 解释：为什么值得注意；
3. 行动：用户同意后可以怎么改。

示例：

> 手指和掌部接得有点生硬。
>
> 手指根部和掌面的连接不够自然，关节转折也有一点突兀。
>
> 可以先调整手指根部和掌面的连接，再顺一下关节方向。其他区域保持不动。

## 首次用户检查问题

每个屏幕都问：

- 用户以为现在发生了什么？这是否符合真实行为？
- 用户是否知道下一步？
- 按钮文字是否准确预测点击后的结果？
- 用户是否理解这是辅助提示，而不是最终判定？
- 示例是否明确标注为示例结果？
- 问题名称、bbox、原因和建议是否指向同一处？
- 失败、无结果、忽略最后一项后是否能继续？

## 验收分级

- **P0**：误导或阻断任务，例如按钮行为不符、错误结果与区域错配、AI 不确定性被写成确定事实、无法恢复。
- **P1**：明显可用性或一致性问题，例如术语混用、下一步不清、等待状态像坏掉、缺少完成状态。
- **P2**：不阻塞交付的文字经济性、节奏或品牌 polish。

有 P0 不能通过验收；无 P0 但有明显 P1 为 CONDITIONAL PASS；仅剩 P2 可 PASS。

## 标准审查输出

先输出：

| 位置 | 当前文案 | UX 问题 | 建议文案 | 依据 | 优先级 |
|---|---|---|---|---|---|

然后只保留三部分：

1. 全局词汇变更；
2. 状态级变更；
3. 仅会改变行为或产品含义的未决问题。

审查必须在真实布局中检查换行、层级、截断、移动端、按钮宽度、空白、重复解释和辅助技术可读性。不要因为“更高级”而无限改写，也不要把 P2 当成阻塞项。
